# 一轮完整长什么样

用一个最普通的场景走一遍：短视频开头文案。
角色分工：**你**负责说哪里不好，**AI** 负责归因、改规则、复查。

---

## 第 0 步 · 先把话说清楚（迭代契约）

```
目标产出：30 字以内的短视频开头
使用者：内容运营
人类评价者：我
硬红线：不许用固定句式模板；不许编造数据
样本来源：过去两周已发布视频的开头
每轮样本量：30 条
收敛标准：连续 3 轮没有新类型的意见
版本命名：V1、V2……
```

## 第 1 步 · 建一版最小规则库

不用一次写全，7～15 条够了。起始规则库在 `RULE-LIBRARY-V1.md`，其中一条是：

> **R005 规则可判定**：能明确判断「符合/不符合」；不能把「高级」「有网感」当唯一标准。

V1 还可以补一条针对本场景的：

```
规则ID：R006
适用条件：开头前 15 字
判断标准：出现「你一定要知道」「今天教你」等通用招呼语 → 不符合
动作：换成这条视频里具体的人物、动作或反常细节
例外：账号定位就是「每日知识科普」，允许用招呼语
优先级：低于 R001（禁止模板化）
证据：过去两周开头数据，完播率最低的 6 条里有 5 条这么写
版本：V1
```

## 第 2 步 · 小批量产出

让 AI 按 V1 写 30 条，每条标注用了哪条规则、哪里拿不准。
**不要**一上来写 4000 条。

## 第 3 步 · 你给负反馈

| 写法 | 能不能用 |
|---|---|
| 「第 7 条不行，改一下」 | ❌ AI 只能瞎猜 |
| 「要更有网感」 | ❌ 没法判断对错 |
| 「第 7 条把结论放在第一句了，观众还不知道在讲什么就先被塞了个答案；如果这条是『先抛结论再论证』的科普型，那放开头可以」 | ✅ 有位置、有原因、有例外 |

30 条里可能只有 8 条有问题，那就只写 8 行反馈。够用。

## 第 4 步 · AI 归因，不改稿

它应该回你一张表，把 8 条反馈归到六类缺口之一：

| 反馈 | 缺口类型 | 候选动作 |
|---|---|---|
| 第 7、12 条结论前置 | 缺规则 | 新增 R007 |
| 第 3 条「节奏还行但偏平」 | 评价标准不清 | 追问什么叫「偏平」 |
| 第 19 条按 R006 判错，但它是科普型 | 例外未定义 | 给 R006 补例外 |

注意：**它不该直接给你一版改好的文案**。改单稿没用，改规则才有复利。

## 第 5 步 · 生成 V2

```
新增 R007：当内容靠悬念推进时，前 15 字不出现最终结论；判断标准、正例、反例、例外、优先级、证据齐备
修改 R006：补「科普型例外」
删除：无
降优先级：无
过拟合风险：R007 来自 2 条样本，先观察一轮再决定是否进冻结版
```

## 第 6 步 · 回归测试

拿黄金集再跑一遍（历史失败样本、最佳样本、边界样本、故意抬杠的对抗样本）：

| 指标 | 结果 |
|---|---|
| 旧错修复率 | 6/6 |
| 新错引入 | 0 |
| 规则冲突 | 0 |
| 不可判定规则 | 0 |
| 结论 | 通过，V2 生效 |

只要有一项不合格，就带着报告回到第 4 步，**不许进全量**。

## 第 7～8 步 · 收敛与铺开

连着 3 轮你提不出新类型的意见、反馈开始重复、盲测也过了 → 冻结 V(n)。
冻结版才拿去处理全量内容，之后抽样质检。上线后新冒出来的意见，开 V(n+1)，**不要原地改冻结版**。

---

## 这一轮里最容易踩的坑

1. 顺手把稿子改了，没写回反馈表 → 这一轮白干。
2. 规则写成「开头要有反差感」→ 不可判定，AI 只能蒙。
3. 觉得 V2 明显更好，跳过回归 → 全量返工，还查不出是哪条规则害的。
4. 一轮就加 12 条规则，没删没合并 → 规则互相打架，越来越死板。
