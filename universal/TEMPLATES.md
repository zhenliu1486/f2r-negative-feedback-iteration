# 模板合订（三张）

## 1. 迭代契约

```
# 迭代契约

- 目标产出：
- 使用者：
- 人类评价者：
- 硬红线：
- 样本来源：
- 每轮样本量：20～50
- 评价维度：
- 收敛标准：连续 3 轮无新缺口类型；反馈重复；盲测通过；人类无法新增有效负反馈；冲突规则为 0；不可判定规则为 0
- 冻结条件：
- 版本命名：V1, V2, ... Vn
- 禁止事项：禁止模板、公式、句式模板作为产出规则；禁止从爆款结果直接反推模板
```

## 2. 规则卡

```
规则ID：
规则名称：
适用条件：
判断标准：满足什么算对，违反什么算错
动作：执行器应该怎么做
正例：
反例：
例外：什么情况下允许违反
优先级：与其它规则冲突时谁优先
证据：来自哪些反馈/样本
版本：
```

## 3. 反馈表（CSV 表头）

```csv
sample_id,output_snippet,what_wrong,why_wrong,when_allowed,gap_type,rule_id,rule_action,severity,evidence
```

## 4. 黄金集表头

| case_id | 类型 | 输入 | 期望判断 | 关联规则ID | 历史失败原因 | 备注 |
|---|---|---|---|---|---|---|
| G001 | 历史失败样本 |  |  |  |  |  |
| G002 | 最佳样本 |  |  |  |  |  |
| G003 | 边界样本 |  |  |  |  |  |
| G004 | 对抗样本 |  |  |  |  |  |

类型包括：历史失败样本、最佳样本、边界样本、对抗样本。每次规则升级必须跑全量黄金集。

## 用法

- 阶段 0 填迭代契约，一份契约对应一个被迭代领域。
- 阶段 3 用反馈表收人类意见，`gap_type` 六选一：缺规则 / 规则模糊 / 规则冲突 / 例外未定义 / 执行偏差 / 评价标准不清。
- 阶段 5 每条新规则写一张规则卡，附 `evidence` 指向反馈表行号或样本 ID。
- 阶段 6 用黄金集表登记测试用例，回归时逐行判定通过与否。
