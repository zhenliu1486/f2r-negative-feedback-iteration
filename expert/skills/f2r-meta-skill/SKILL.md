# F2R 负反馈规则迭代元技能
Feedback-to-Rules Meta-Skill / V1.0

## 0. 一句话定义

不教 AI 模仿结果，不喂爆款模板；用负反馈把人的隐性判断显性化为可判定规则，小样本高频迭代，回归测试，收敛后全量执行。

核心关系：

> 稳定产出 = 规则库 × 执行一致性 × 回归测试
> 规则库 = 负反馈归因 + 反例 + 例外 + 优先级 + 版本记录

## 1. 适用与不适用

适用：写文案、短视频开头、数据清洗、SOP 设计、代码风格、设计评审、销售话术、客服流程、制作 Skill、制作 Agent、系统提示词迭代，以及任何“需要人判断好坏并希望复制”的工作。

不适用：一次性任务；没有反馈源；没有人类价值判断；纯安全合规硬约束且不可协商的部分。后者应写成“硬红线”，不参与自由迭代。

## 2. 核心原则

1. 规则 > 结果。结果只用于暴露规则缺口，不作为模板来源。
2. 不学“爆款长啥样”，学“爆款如何被塑造”。禁止让 AI 分析爆款结果后直接总结模板。
3. 负反馈优先。每次反馈必须回答三问：
   1）哪句/哪步不好；
   2）为什么不好；
   3）什么情况下可以这么写/这么做。
4. 规则必须可判定。规则卡 = 适用条件 + 判断标准 + 动作 + 正例 + 反例 + 例外 + 优先级 + 证据。
5. 红线：被迭代领域的提示词里禁止出现模板、公式、句式模板作为产出规则。规则不是“照这个句式写”，而是“什么条件下判断为对/错，为什么，何时例外”。
6. 小样本高频迭代，稳定后全量。每轮 20～50 个样本，不直接全量。
7. 人机分工：人负责价值判断、好坏判断、例外批准；AI 负责执行、归因、提炼候选规则、回归测试、自动化编排。
8. 语文转数学。在规则体系内，评价不是“好坏”，而是“符合/不符合哪条规则”；无法判定，就说明规则缺失或模糊。
9. 版本化、可追溯、可回归。每个版本必须有规则 diff、反馈表、回归结果、变更理由。
10. 收敛而非完美。连续多轮无新规则类型、反馈重复、盲测通过、人类无法新增负反馈，即冻结。

## 3. 角色分工

- 人类评价者：判断好坏、为什么、例外；批准规则；不可替代。
- 执行器 Agent：按当前规则库产出。
- 反馈审计器：判断人类反馈是否足够具体，不够则追问。
- 规则迭代器：根据历史版本、产出、反馈生成 V(n+1) 候选规则。
- 回归测试器：用黄金集检查旧错是否修复、新错是否引入、规则是否冲突。
- 版本管理员：维护规则卡、反馈表、changelog、冻结版本。
- 总控 Orchestrator：编排循环，未通过回归不得进入全量。

## 4. 通用总流程：F2R 收敛环

### 阶段 0：迭代契约
写清楚：目标产出、使用者、评价者、硬红线、样本来源、每轮样本量、收敛标准、冻结条件、版本命名。

### 阶段 1：建立 V1 最小规则集
不要追求完整。先写 7～15 条规则卡。不会写规则就写“绝对不要”和“必须满足”的反例清单。禁止写模板公式。

### 阶段 2：小批量执行
执行器按 V1 产出 20～50 个样本。

### 阶段 3：人类负反馈
人类只做三问 + 严重度 + 例外。可以顺手改稿，但改稿必须沉淀成反馈表，否则无效。

### 阶段 4：AI 归因
把反馈聚类为六类规则缺口：
缺规则 / 规则模糊 / 规则冲突 / 例外未定义 / 执行偏差 / 评价标准不清。
输出候选规则卡，不直接改产出。

### 阶段 5：生成 V(n+1)
做规则增、删、改、合并、降优先级。每条新规则必须有证据、反例、例外、优先级。防止过拟合单个样本。

### 阶段 6：回归测试
黄金集 = 历史失败样本 + 最佳样本 + 边界样本 + 对抗样本。
检查：旧错修复率、新错引入率、规则冲突数、不可判定规则数。不通过则回到阶段 4。

### 阶段 7：收敛判定
满足以下条件可冻结：
连续 3 轮无新缺口类型；反馈开始重复；盲测通过；人类无法提出新的有效负反馈；冲突规则为 0；不可判定规则为 0。

### 阶段 8：全量执行与监控
冻结版一次性处理全量，抽样质检。上线后新反馈进入下一轮版本迭代。

## 6. 规则质量门禁

一条规则进入规则库前必须通过：

- 可判定：能明确判断符合/不符合。
- 可执行：执行器知道具体做什么。
- 有反例：知道什么算错。
- 有例外：知道何时允许。
- 有优先级：冲突时有裁决。
- 无模板化：不是“照这个句式/结构写”。
- 无过拟合：不是只服务一个样本。
- 可回归：能放进黄金集测试。

反模式：喂爆款模板；让 AI 分析爆款结果直接总结公式；人类只改稿不写反馈；规则写成“要高级”“要有网感”这类不可判定话；规则太多无优先级；跳过小样本直接全量；只收正反馈；把主观判断当成不可说。

## 7. 自动化编排

五个子 Skill + 一个总控：

1. Skill Executor：按规则库产出。
2. Human Critic：人类负反馈入口。
3. Skill Feedback Auditor：判断反馈是否足够迭代；不够就追问。
4. Skill Rule Updater：根据历史版本、产出、反馈生成 V(n+1)。
5. Skill Regression Tester：跑黄金集，输出通过/不通过。
6. Orchestrator：循环调度，未通过回归不得全量。

伪循环：

```text
while not converged:
  outputs = Executor(rules_v)
  feedback = HumanCritic(outputs)
  if not FeedbackAuditor(feedback):
      追问人类，直到反馈足够
  rules_new = RuleUpdater(history, outputs, feedback)
  report = RegressionTester(rules_new)
  if report.pass:
      rules_v = rules_new
      log_version()
  else:
      feedback += report
freeze(rules_v)
run_full()
```

## 8. 收敛条件

连续 3 轮无新缺口类型；反馈重复；盲测通过；人类无法新增有效负反馈；冲突规则为 0；不可判定规则为 0。

## 9. 总口诀

不学结果，学塑造；不喂模板，喂反馈；不改单稿，改规则；小样本迭代，回归后全量；规则可判定，版本可追溯；人判断好坏与例外，AI 执行、归因、迭代、测试；收敛即冻结，冻结再复制。
